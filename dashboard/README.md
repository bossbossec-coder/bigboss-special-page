# 多店舗売上ダッシュボード（ローカル・プロトタイプ）

10店舗以上の日次売上Excelを決まったフォルダに置くだけで、
日別売上・前年同日比・月進捗・月末着地予測を見られるダッシュボードです。
まずはローカルで動くプロトタイプとして作成しています。

## フォルダ構成

```
dashboard/
├── app.py                      # ダッシュボード本体（Streamlit）
├── lib/data_loader.py          # Excel読み込み・集計ロジック
├── scripts/generate_sample_data.py  # 動作確認用サンプルデータ生成
├── scripts/generate_template.py     # 記入用テンプレートの生成スクリプト
├── templates/日次売上_入力テンプレート.xlsx  # ← 各店舗に配布する記入用Excel
├── data/incoming/              # ← 各店舗が実績を入れたExcelを置く場所
└── requirements.txt
```

## 記入用テンプレート（実際の数値を入力する場合）

`templates/日次売上_入力テンプレート.xlsx` が、各店舗に配布してそのまま
数値を入力してもらうためのExcelです。

- **「使い方」シート**: 運用ルールの説明
- **「店舗マスタ」シート**: プルダウンに出す店舗名の一覧。サンプル店舗名
  （渋谷店・新宿店…）が仮で入っているので、**実際の店舗名に書き換えて**
  ください。行が足りなければ追加できます。
- **「売上入力」シート**: 実際に日々入力していくシート。店舗名はプルダウン
  で選べるようになっており、表記ゆれ（「渋谷店」/「渋谷」など）を防げます。

運用イメージは「店舗ごとに1ファイルを作り、日々その中に1行ずつ実績を
追記していく」形です（`渋谷店_売上.xlsx` のように店舗が分かるファイル名に
して `data/incoming/` に置いてください）。もちろん、これまで通り「1日1
ファイル」の運用でも問題なく集計できます。

店舗マスタの内容を変更した場合や、テンプレートを作り直したい場合は
次のコマンドで再生成できます（`店舗マスタ` の書き換え内容は上書きされる
ため、スクリプト側の `PLACEHOLDER_STORES` を実際の店舗名リストに直して
から実行するのがおすすめです）。

```bash
python3 scripts/generate_template.py
```

## Excelファイルのフォーマット仕様

各店舗は **1日1ファイル** を `data/incoming/` に置きます。
ファイル名はソートしやすいよう次の形式を推奨します（必須ではありません。
実際の集計はファイル内の「日付」「店舗名」列を見て行うため、ファイル名が多少
ずれても動作します）。

```
YYYYMMDD_店舗名.xlsx     例: 20260912_渋谷店.xlsx
```

シートの列構成（シート名が「売上入力」または「売上」ならそれを読み込み、
無ければ必須列を持つ最初のシート、それも無ければ1枚目のシートを読み込みます。
記入用テンプレートの他のシート「使い方」「店舗マスタ」は無視されます）:

| 列名（1行目のヘッダー） | 必須 | 内容 | 例 |
|---|---|---|---|
| 日付 | ○ | その日の日付 | 2026-09-12 |
| 店舗名 | ○ | 店舗名（表記を店舗間で統一） | 渋谷店 |
| 売上金額 | ○ | その日の売上合計（円、数値） | 523400 |
| 客数 | - | 来客数（任意、未入力可） | 182 |
| 備考 | - | 任意のメモ | 棚卸のため短縮営業 |

- 1ファイル1行（その日・その店舗の合計）を基本形とします。
- 同じ日付・店舗のデータが複数ファイル／複数行に分かれて存在する場合は、
  自動的に合算されます（カテゴリ別に複数行を置く運用にも対応可能）。
- 列名が1つでも欠けている、または日付・売上金額が正しく読めないファイルは
  読み込みをスキップし、ダッシュボード上に警告として一覧表示されます
  （1店舗の入力ミスで全体が止まらない設計です）。

店舗名の表記は必ず統一してください（例: 「渋谷店」と「渋谷」が混在すると
別店舗として集計されます）。

### 店舗の表示順

グラフ・テーブルでの店舗の並び順は、`app.py` の `STORE_DISPLAY_ORDER`
で固定しています。ここに無い店舗名は、末尾にアルファベット順で自動的に
追加されます。並び順を変更したい場合は `STORE_DISPLAY_ORDER` のリストを
書き換えてください。

### 外販（スポット売上）の扱い

店舗名に **「外販」** と入力した行は、通常の店舗売上とは別枠の
「外販売上」として扱われます。店舗別の合計・ランキング・前年比・
月別前年比・年間前年比など、店舗に関する集計には一切含まれません
（スポットでたまにしか発生しない売上のため、店舗の数値に混ぜない
設計です）。ダッシュボード下部に、外販だけの本日売上・前年同日比・
当月累計が別途表示されます。列構成・入力方法は店舗の行と同じです。

## 動作確認用サンプルデータの生成

実際のExcelがまだ揃っていない段階でも、ダッシュボードの動きを確認できます。

```bash
python3 scripts/generate_sample_data.py
```

10店舗 × 約13か月分のサンプルExcelが `data/incoming/` に生成されます
（前年同日比・月進捗・月末着地予測がすべて確認できるボリュームです）。
本番運用の前にこのサンプルファイルは削除してください。

## 起動方法

```bash
streamlit run app.py
```

ブラウザで `http://localhost:8501` が開きます。サイドバーで
「Excelフォルダ」のパス、対象月、基準日（本日扱いにする日付）、店舗を
切り替えられます（基準日の初期値は「前日」です。当日はまだ入力が
終わっていないことが多いためです）。右上の「🔧 対象日・表示店舗を変更」
ボタンからも同じ基準日・店舗の変更ができ、サイドバーと常に連動します。

画面構成（上から順）:

- **売上サマリー**: 本日売上・前年同日比・当月累計・月末着地予測のKPIを、
  色分けしたブロックで表示（本日の売上合計=濃い青、前年同日比=緑、
  当月累計=赤、月末着地予測=黒、文字はすべて白）。本日の売上合計の
  下段には前年との差額を＋－付きで、当月累計・月末着地予測の下段には
  対比％を表示（前年同日比のカードは値自体が対比％のため下段は表示なし）。
  右上には「表示店舗」（現在の店舗フィルター状況）と「対象日」を
  バッジで並べて表示（対象日バッジの左側に西暦を縦書きで表示）。
  本日の売上合計・当月累計・
  月末着地予測には、対比％に応じた記号を数値の左に表示する
  （◎150%以上・〇149~100%・▽99~90%・×89%以下。前年同日比自体は
  対比％そのものを表示する値のため記号は付けない）。本日の売上合計は
  前年同日、当月累計・月末着地予測は前年同月を基準に判定する
- **グループ日別売上（今年 vs 前年同月）**: 月内の日を揃えて今年と前年を比較
  （店舗フィルターで絞った、または全店舗合算の「グループ」の日別推移。
  今年のバーは本日の売上合計カードと同じ青色）
- **月進捗**: 当月の経過日数をグラデーションのプログレスバーで表示。
  あわせて累計・平均・着地予測
- **店舗別・日別売上**: 基準日1日分の店舗ごとの売上を、当日（オレンジ）・
  前年同日（グレー）の棒グラフで比較したあと、前年同日の
  売上・前年同日比、当月累計の前年比とあわせて一覧表示するテーブル
  （対象日はタイトル下に表示）

  ↓ ここから下は「日別」から「月別」の集計に切り替わるため、
  太いグラデーションの区切り線を入れている

- **店舗別・月別売上**: 当月累計（オレンジ）・前年同期間（グレー）の
  棒グラフに前年売上計（折れ線）を重ねて比較したあと、当月累計売上・
  前年同期間売上・前年比・前年売上計（前年同月のフル月合計、参考値）を
  店舗ごとに表示
- **グループ月別前年比（直近12ヶ月）**: 基準日から遡った12ヶ月分を、月ごとに
  前年同月と比較（グラフ＋表）。グラフは古い月→新しい月の時系列順、
  表は新しい月が上に来る降順で並べている。基準日を含む月（営業途中の月）は、
  今年・前年とも「月初から基準日と同じ日数分」で揃えて比較する
- **年間前年比**: 今年の年初〜基準日までの累計と、
  前年同期間累計・前年比・前年フル暦年実績を表示
- **記録（日商ギネス・月商ギネス）**: これまでの全期間の中で、1日の売上が
  最も高かった記録（日商ギネス、1店舗単位）と、月間売上が最も高かった記録
  （月商ギネス、外販を除く全店舗合計・グループ全体）を、売上高・達成日付
  とあわせて表示
- **外販売上**: 店舗名が「外販」の実績だけを集計した、本日売上・前年同日比・
  当月累計（月末着地予測なし）。店舗の合計・ランキング・前年比などには
  一切含まれない、独立した集計です

KPIカードの金額は桁が大きいと見切れてしまうため、億・万円単位で
省略表示しています（例: ¥14.07億）。正確な金額はカードの ⓘ にカーソルを
合わせる（スマホはタップ）と確認できます。

前年との比較はすべて「対比％」（今年÷前年×100）で統一しています。
100%が前年と同水準、100%より大きければ前年超え、小さければ前年割れです
（例: 前年比95%＝前年の95%の水準、前年比110%＝前年の1.1倍）。
KPIカードの前年差分（デルタ）は、金額差（億・万円単位）と対比％を
あわせて表示し、緑の上向き矢印が前年超え、赤の下向き矢印が前年割れを
示します。

## PC・スマートフォン表示について

Streamlit標準のレイアウト機能により、画面幅が狭い場合は列（KPIカードや
グラフ）が自動的に縦積みに切り替わります。スマートフォン幅（640px以下）
では見出しやKPIカードの文字サイズを詰めるなど、画面に収まりやすいよう
調整しています。PCのブラウザ幅を狭めるか、スマートフォンの実機・
ブラウザの端末シミュレーターで確認できます。

## 月末着地予測の考え方

2種類のロジックを使い分けます。

1. **前年同月比ベース**（前年の同期間データがある場合）:
   `前年同月の実績 × 伸び率`
   季節性（曜日構成など）を前年の実績からある程度引き継げる方法です。

   伸び率は「今年の当月累計 ÷ 前年の同期間累計」だけで決めると、
   月初（経過日数が少ない時）はたまたまの1日の変動に予測全体が
   引っ張られてブレやすくなります。そのため、直近3ヶ月分の
   「実績ベースの前年比」の平均値も土台として用意しておき、
   月初のうちはその土台値を重めに、日数が経つにつれて今月実績の
   伸び率を重めに、経過日数の割合に応じて混ぜ合わせています。
   月末に近づくほど自然に今月実績だけの伸び率に収束するため、
   月末時点の精度は変えずに、月初〜月中のブレだけを抑えています。
2. **単純日次平均ベース**（前年データがない場合のフォールバック）:
   `当月累計 ÷ 経過日数 × 当月の日数`

どちらの方法を使ったかはKPIカードの補足に表示されます。

## クラウド公開（店長など複数人に見てもらう場合）

「入力するのは自分だけ、閲覧は各店舗の店長にもしてもらいたい」という
運用のために、Streamlit Community Cloud（無料）にデプロイして、
ブラウザの「データ登録」欄からExcelをアップロードできる仕組みを
用意しています。詳しい手順は別紙の設定ガイドを参照してください。
ここでは仕組みの概要だけまとめます。

- サイドバー下部の「📤 データ登録（Excelアップロード）」から、
  `data/incoming/` にファイルを置くのと同じ内容をブラウザ経由で登録できる
  （ローカルでフォルダに直接置く方法と併用可能）
- Streamlit Cloudの「Secrets」に `admin_password` を設定すると、この欄が
  パスワードで保護される（設定しなければローカル実行時と同様、誰でも
  すぐ使える状態のまま）
- Secretsに `github_token` / `github_repo` / `github_branch` も設定すると、
  アップロードのたびにファイルがGitHubリポジトリ側にも保存され、
  アプリが再起動してもデータが消えない（`.streamlit/secrets.toml.example`
  に設定項目の見本があります）
- 店長など閲覧だけする人には、Streamlit Cloudが発行するURLを渡すだけでよい
  （パスワードなしでダッシュボードの閲覧ができ、アップロード欄だけが
  保護される）

## 今後の拡張候補

これはローカルで動く第一プロトタイプから始まっています。運用に合わせて
さらに以下を検討できます。

- フォルダを社内サーバーの共有フォルダに向け、定期実行（cron等）やファイル監視で
  自動更新する
- 店舗ごとの目標値（予算）を別シートで持たせ、予算比も表示する
- カテゴリ別・時間帯別など、Excelの列を増やした際の集計軸の追加
- 不正な値や未提出店舗をアラート表示する仕組み
