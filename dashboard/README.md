# 多店舗売上ダッシュボード（ローカル・プロトタイプ）

10店舗以上の日次売上Excelを決まったフォルダに置くだけで、
日別売上・前年同日比・月進捗・月末着地予測を見られるダッシュボードです。
まずはローカルで動くプロトタイプとして作成しています。

## フォルダ構成

```
dashboard/
├── app.py                      # ダッシュボード本体（Streamlit）
├── lib/data_loader.py          # Excel読み込み・集計ロジック
├── scripts/generate_sample_data.py  # 動作確認用サンプルデータ生成
├── scripts/generate_template.py     # 記入用テンプレートの生成スクリプト
├── templates/日次売上_入力テンプレート.xlsx  # ← 各店舗に配布する記入用Excel
├── data/incoming/              # ← 各店舗が実績を入れたExcelを置く場所
└── requirements.txt
```

## 記入用テンプレート（実際の数値を入力する場合）

`templates/日次売上_入力テンプレート.xlsx` が、各店舗に配布してそのまま
数値を入力してもらうためのExcelです。

- **「使い方」シート**: 運用ルールの説明
- **「店舗マスタ」シート**: プルダウンに出す店舗名の一覧。サンプル店舗名
  （渋谷店・新宿店…）が仮で入っているので、**実際の店舗名に書き換えて**
  ください。行が足りなければ追加できます。
- **「売上入力」シート**: 実際に日々入力していくシート。店舗名はプルダウン
  で選べるようになっており、表記ゆれ（「渋谷店」/「渋谷」など）を防げます。

運用イメージは「店舗ごとに1ファイルを作り、日々その中に1行ずつ実績を
追記していく」形です（`渋谷店_売上.xlsx` のように店舗が分かるファイル名に
して `data/incoming/` に置いてください）。もちろん、これまで通り「1日1
ファイル」の運用でも問題なく集計できます。

店舗マスタの内容を変更した場合や、テンプレートを作り直したい場合は
次のコマンドで再生成できます（`店舗マスタ` の書き換え内容は上書きされる
ため、スクリプト側の `PLACEHOLDER_STORES` を実際の店舗名リストに直して
から実行するのがおすすめです）。

```bash
python3 scripts/generate_template.py
```

## Excelファイルのフォーマット仕様

各店舗は **1日1ファイル** を `data/incoming/` に置きます。
ファイル名はソートしやすいよう次の形式を推奨します（必須ではありません。
実際の集計はファイル内の「日付」「店舗名」列を見て行うため、ファイル名が多少
ずれても動作します）。

```
YYYYMMDD_店舗名.xlsx     例: 20260912_渋谷店.xlsx
```

シートの列構成（シート名が「売上入力」または「売上」ならそれを読み込み、
無ければ必須列を持つ最初のシート、それも無ければ1枚目のシートを読み込みます。
記入用テンプレートの他のシート「使い方」「店舗マスタ」は無視されます）:

| 列名（1行目のヘッダー） | 必須 | 内容 | 例 |
|---|---|---|---|
| 日付 | ○ | その日の日付 | 2026-09-12 |
| 店舗名 | ○ | 店舗名（表記を店舗間で統一） | 渋谷店 |
| 売上金額 | ○ | その日の売上合計（円、数値） | 523400 |
| 客数 | - | 来客数（任意、未入力可） | 182 |
| 備考 | - | 任意のメモ | 棚卸のため短縮営業 |

- 1ファイル1行（その日・その店舗の合計）を基本形とします。
- 同じ日付・店舗のデータが複数ファイル／複数行に分かれて存在する場合は、
  自動的に合算されます（カテゴリ別に複数行を置く運用にも対応可能）。
- 列名が1つでも欠けている、または日付・売上金額が正しく読めないファイルは
  読み込みをスキップし、ダッシュボード上に警告として一覧表示されます
  （1店舗の入力ミスで全体が止まらない設計です）。

店舗名の表記は必ず統一してください（例: 「渋谷店」と「渋谷」が混在すると
別店舗として集計されます）。

### 店舗の表示順

グラフ・テーブルでの店舗の並び順は、`app.py` の `STORE_DISPLAY_ORDER`
で固定しています。ここに無い店舗名は、末尾にアルファベット順で自動的に
追加されます。並び順を変更したい場合は `STORE_DISPLAY_ORDER` のリストを
書き換えてください。

### 外販（スポット売上）の扱い

店舗名に **「外販」** と入力した行は、通常の店舗売上とは別枠の
「外販売上」として扱われます。店舗別の合計・ランキング・前年比・
月別前年比・年間前年比など、店舗に関する集計には一切含まれません
（スポットでたまにしか発生しない売上のため、店舗の数値に混ぜない
設計です）。ダッシュボード下部に、外販だけの本日売上・前年同日比・
当月累計が別途表示されます。列構成・入力方法は店舗の行と同じです。

```bash
cd dashboard

```

## 動作確認用サンプルデータの生成

実際のExcelがまだ揃っていない段階でも、ダッシュボードの動きを確認できます。

```bash
python3 scripts/generate_sample_data.py
```

10店舗 × 約13か月分のサンプルExcelが `data/incoming/` に生成されます
（前年同日比・月進捗・月末着地予測がすべて確認できるボリュームです）。

## 起動方法

```bash
streamlit run app.py
```

ブラウザで `http://localhost:8501` が開きます。サイドバーで
「Excelフォルダ」のパス、対象月、基準日（本日扱いにする日付）、店舗を
切り替えられます（基準日の初期値は「前日」です。当日はまだ入力が
終わっていないことが多いためです）。右上の「🔧 対象日・表示店舗を変更」
ボタンからも同じ基準日・店舗の変更ができ、サイドバーと常に連動します。

画面構成（上から順）:

- **売上サマリー**: 本日売上・前年同日比・当月累計・月末着地予測のKPIを、
  色分けしたブロックで表示（本日の売上合計=濃い青、前年同日比=緑、
  当月累計=赤、月末着地予測=黒、文字はすべて白）。本日の売上合計の
  下段には前年との差額を＋－付きで、当月累計・月末着地予測の下段には
  対比％を表示（前年同日比のカードは値自体が対比％のため下段は表示なし）。
  右上には「表示店舗」（現在の店舗フィルター状況）と「対象日」を
  バッジで並べて表示（対象日バッジの左側に西暦を縦書きで表示）。
  本日の売上合計・当月累計・
  月末着地予測には、対比％に応じた記号を数値の左に表示する
  （◎150%以上・〇149~100%・▽99~90%・×89%以下。前年同日比自体は
  対比％そのものを表示する値のため記号は付けない）。本日の売上合計は
  前年同日、当月累計・月末着地予測は前年同月を基準に判定する
- **グループ日別売上（今年 vs 前年同月）**: 月内の日を揃えて今年と前年を比較
  （店舗フィルターで絞った、または全店舗合算の「グループ」の日別推移。
  今年のバーは本日の売上合計カードと同じ青色）
- **月進捗**: 当月の経過日数をグラデーションのプログレスバーで表示。
  あわせて累計・平均・着地予測
- **店舗別・日別売上**: 基準日1日分の店舗ごとの売上を、当日（オレンジ）・
  前年同日（グレー）の棒グラフで比較したあと、前年同日の
  売上・前年同日比、当月累計の前年比とあわせて一覧表示するテーブル
  （対象日はタイトル下に表示）

  ↓ ここから下は「日別」から「月別」の集計に切り替わるため、
  太いグラデーションの区切り線を入れている

- **店舗別・月別売上**: 当月累計（オレンジ）・前年同期間（グレー）の
  棒グラフに前年売上計（折れ線）を重ねて比較したあと、当月累計売上・
  前年同期間売上・前年比・前年売上計（前年同月のフル月合計、参考値）を
  店舗ごとに表示
- **グループ月別／年別前年比（12ヶ月／12年表示）**: 見出しの右にある「月」
  「年」ボタン（店舗別・日別売上の「日」「月」ボタンと同じ大きさ）で、
  月単位・年単位の表示を切り替えられる（グラフ・表とも連動）。
  - 月表示: 12ヶ月分を、月ごとに前年同月と比較（当年バーは緑、前年同月バー
    はグレー）。基準日を含む月（営業途中の月）は、今年・前年とも
    「月初から基準日と同じ日数分」で揃えて比較する
  - 年表示: 12年分を、年ごとの売上を1本のバーで表示し、基準日を含む年
    （今年）だけ青、それ以外の完了済みの年はグレーで表示する（当年の色は
    月表示の緑と区別するため青にしている）。基準日を含む年は、今年・前年
    とも「年始から基準日と同じ日数分」で揃えて比較する
  - グラフは古い→新しい時系列順で、グラフのすぐ上にある丸い「◀」「▶」
    ボタンで表示期間を1画面分（月表示は12ヶ月、年表示は12年）さかのぼって
    見られる（最新の期間を表示中は「▶」が押せない）。表の方はグラフの
    表示期間・モードに関わらず、データがある全期間をそれぞれ月表示・年表示
    で新しい方が上に来る降順で含み、12行分の高さで表示（13行分以上ある
    場合は表内をスクロール）
- **年間前年比**: 今年の年初〜基準日までの累計と、
  前年同期間累計・前年比・前年フル暦年実績を表示
- **記録（日商ギネス・月商ギネス）**: これまでの全期間の中で、1日の売上が
  高かった記録（日商ギネス、1店舗単位）と、月間売上が高かった記録
  （月商ギネス、外販を除く全店舗合計・グループ全体）を、それぞれ上位3件、
  年間前年比と同じst.metricの並び（順位・達成日を見出しに、金額を大きく
  表示。正確な金額はカーソルを合わせると確認できる）で表示
- **外販売上**: 店舗名が「外販」の実績だけを集計した、本日売上・前年同日比・
  当月累計（月末着地予測なし）。店舗の合計・ランキング・前年比などには
  一切含まれない、独立した集計です

KPIカードの金額は桁が大きいと見切れてしまうため、億・万円単位で
省略表示しています（例: ¥14.07億）。正確な金額はカードの ⓘ にカーソルを
合わせる（スマホはタップ）と確認できます。

前年との比較はすべて「対比％」（今年÷前年×100）で統一しています。
100%が前年と同水準、100%より大きければ前年超え、小さければ前年割れです
（例: 前年比95%＝前年の95%の水準、前年比110%＝前年の1.1倍）。
KPIカードの前年差分（デルタ）は、金額差（億・万円単位）と対比％を
あわせて表示し、緑の上向き矢印が前年超え、赤の下向き矢印が前年割れを
示します。

## 画面のテーマ（配色）について

`.streamlit/config.toml` で、常にライトテーマ（明るい配色）で表示されるよう
固定しています。これが無いと、閲覧する人のスマホ・ブラウザが「ダークモード」
設定になっている場合に、ダッシュボードの背景が黒っぽくなってしまい、
一部の文字（表の中身など）が背景色と同化して読めなくなる不具合がありました。
固定しているため、閲覧者側の設定に関わらず常に同じ見た目で表示されます。

## PC・スマートフォン表示について

Streamlit標準のレイアウト機能により、画面幅が狭い場合は列（KPIカードや
グラフ）が自動的に縦積みに切り替わります。スマートフォン幅（640px以下）
では見出しやKPIカードの文字サイズを詰めるなど、画面に収まりやすいよう
調整しています。PCのブラウザ幅を狭めるか、スマートフォンの実機・
ブラウザの端末シミュレーターで確認できます。

「店舗別・日別売上」の表は、PC/タブレットでは従来通りの列数のままですが、
スマートフォン幅では横スクロールが発生しないよう、列を絞ったコンパクトな表
（店舗・当日売上・前年同日比）に自動的に切り替わります。「店舗別・月別売上」
の表はスマートフォンでも全列を表示しますが、1列目（店舗名）を固定した
まま残りの列だけを横スクロールできるようにしています。

「店舗別・日別売上」「店舗別・月別売上」の表（PC/タブレット）は、店舗名の列を
中央揃え、それ以外の数値列を右揃えにしています。また、該当する前年比
（日別表は「前年同日比」、月別表は「前年比」）が99.9%以下の店舗は、行全体を
薄い赤色にして一目で分かるようにしています。見出し（「####」の太字部分）も
PC/タブレットでは中央揃えにしています（スマートフォンでは左揃えのまま）。

PC/タブレットのグラフは、Y軸のタイトルは残したまま、目盛りを「30M」のような
英語の省略表記ではなく「3,000万」「3千万」のような日本語の単位表記にし
（スマートフォン版と同じ単位ロジック）、グラフの高さもこれまでの1.5倍に
拡大しています。

「店舗別・日別売上」グラフの上には、店舗ごとの売上を売上サマリーのような
色付きカードで表示するブロックがあります（PCでは4列、スマートフォンでは
2列）。上部の「日」「月」ボタンで、カードの中身と色を日別（青・当日売上/
前年同日売上・前年同日比）と月別（オレンジ・当月累計/前年同期間累計・
当月累計前年比）に切り替えられます（金額は万単位の整数値のみ、「/」区切りは
小さく表示、切り替え時は軽いアニメーション付き）。

スマートフォンでは、これ以外にも次の表示をPC/タブレットと分けています
（PC/タブレット側の見た目はすべて従来通りです）。

- 「表示店舗」「対象日」のバッジを、サイズと高さを揃えて横並びのまま1行に収める
- 「対象日・表示店舗を変更」ボタンは、バッジとの間を狭く、下のKPIブロックとの
  間を広くする
- 「本日の売上合計」〜「月末着地予測」の4枚のKPIブロックを、縦1列ではなく
  2列×2行で表示
- 棒グラフのY軸のタイトル文字を非表示にする（目盛りの日本語単位表記はPCと共通）
- 画面左下に、タップすると画面の最上部までスクロールして戻る丸いボタンを表示
  （スクロール中は薄く表示され、止まると元の濃さに戻る）

グラフの色は、「店舗別・日別売上」の当日売上バーは「本日の売上合計」カードと
同じ青、「グループ月別前年比」（月表示）の当年バーは緑に統一しています
（PC/スマホ共通）。同じ場所の年表示では、当年（今年）バーは青、それ以外の
年はグレーで、月表示の緑と見分けられるようにしています。

## 月末着地予測の考え方

2種類のロジックを使い分けます。

1. **前年同月比ベース**（前年の同期間データがある場合）:
   `前年同月の実績 × 伸び率`
   季節性（曜日構成など）を前年の実績からある程度引き継げる方法です。

   伸び率は「今年の当月累計 ÷ 前年の同期間累計」だけで決めると、
   月初（経過日数が少ない時）はたまたまの1日の変動に予測全体が
   引っ張られてブレやすくなります。そのため、直近3ヶ月分の
   「実績ベースの前年比」の平均値も土台として用意しておき、
   月初のうちはその土台値を重めに、日数が経つにつれて今月実績の
   伸び率を重めに、経過日数の割合に応じて混ぜ合わせています。
   月末に近づくほど自然に今月実績だけの伸び率に収束するため、
   月末時点の精度は変えずに、月初〜月中のブレだけを抑えています。
2. **単純日次平均ベース**（前年データがない場合のフォールバック）:
   `当月累計 ÷ 経過日数 × 当月の日数`

どちらの方法を使ったかはKPIカードの補足に表示されます。

## 予定表（Googleカレンダーの埋め込み）

ダッシュボード最下部に、Googleカレンダーの予定表を埋め込み表示できます。

1. Googleカレンダーで表示したい予定表の「設定と共有」を開く
2. 「アクセス権限」で、店長さんたちがログイン無しでも見られるよう
   「一般公開にする」にチェックする（社内限定の内容なら「予定の詳細」
   ではなく「予定の有無のみ」を選ぶ方が安全）
3. 「予定表の統合」欄にある埋め込みコードから、`src="https://calendar.google.com/calendar/embed?..."`
   の `src=` の中身（URL部分）をコピーする
4. Streamlit Cloudの「Secrets」（またはローカルの`.streamlit/secrets.toml`）に
   `google_calendar_src` としてそのURLを設定する（`.streamlit/secrets.toml.example`
   に見本があります）

`google_calendar_src` を設定した場合のみ、ダッシュボード最下部に「予定表」の
見出しとカレンダーが表示されます。設定しなければ、これまで通り予定表は
一切表示されません。見た目（配色・フォント）はGoogle側のものがそのまま
表示され、アプリ全体のデザインとは別枠になります。

## 新商品情報（アサヒ・キリン・サントリー・サッポロ）

ダッシュボード最下部（予定表のさらに下）に、アサヒ・キリン・サントリー・
サッポロ4社の新商品情報を自動表示しています（`lib/beverage_news.py`）。

- 各社が「PR TIMES」というプレスリリース配信サービスに出している発表の中から、
  タイトルに「新発売」「新商品」などのキーワードを含むものだけを抽出し、
  新しい順に各社最大5件まで表示します
- 表示のたびに毎回取得しに行くと重くなるため、6時間キャッシュしています
  （更新したい場合はアプリの再起動、またはキャッシュの有効期限切れを待つ）
- 特定のメーカーだけ「現在情報を取得できません」と表示される場合、その
  メーカーの取得先（PR TIMESの企業ID）が変わった・情報源側の不具合、
  などが考えられます。その場合は`lib/beverage_news.py`内の
  `PR_TIMES_COMPANY_IDS`を見直してください
- この開発環境からは外部サイトへの接続を試せなかったため、実際にどこまで
  正確に新商品だけが表示されるかは、本番環境（Streamlit Cloud）で表示を
  見て確認・調整が必要です

## 地域情報（松戸市・鎌ケ谷市）

新商品情報のさらに下に、松戸市・鎌ケ谷市の「お知らせ・新着情報」と
地域ニュース（松戸経済新聞・千葉日報 鎌ケ谷版）を自動表示しています
（`lib/local_news.py`）。仕組みは新商品情報と同じで、各情報源のRSS等の
配信情報から新しい順に最大5件を表示し、6時間キャッシュします。

**取得先URLはこの開発環境からは検証できていません。** 松戸市・鎌ケ谷市の
公式サイトや地域ニュースサイトへの接続をこの開発環境からは試せないため、
`lib/local_news.py`内の`LOCAL_NEWS_SOURCES`は、情報源ごとに複数の候補URLを
リストで持たせ、実際にフィードとして読み込めた最初のURLを自動的に使う
つくりにしています（`feed_utils.fetch_feed_items()`側の仕組み）。それでも
「現在情報を取得できません」のままになっている情報源があれば、該当サイトの
RSS配信ページを確認したうえで、候補URLのリストに追加・修正してください
（多くの場合、サイトのフッターやトップページに「RSS」のリンクがあります）。

## 酒販店小売業ニュース

地域情報のさらに下に、酒販店小売業に関するニュース（全国小売酒販組合中央会・
酒類食品産業新聞）を自動表示しています（`lib/liquor_retail_news.py`）。
仕組みは新商品情報・地域情報と同じで、各情報源のRSS等の配信情報から新しい順に
最大5件を表示し、6時間キャッシュします。

こちらも同様に、`LIQUOR_RETAIL_NEWS_SOURCES`は候補URLのリスト形式にしており、
取得できない情報源があれば候補URLを見直し・追加してください。

なお、新商品情報・地域情報・酒販店小売業ニュースの3つのセクションは、
フィード取得の共通処理を`lib/feed_utils.py`にまとめています。今後
新しい情報源を追加する場合も、「表示名 -> フィードURL（1件、または候補の
リスト）」の辞書を用意して`feed_utils.fetch_feed_items()`を呼び出すだけで
対応できます。

「入力するのは自分だけ、閲覧は各店舗の店長にもしてもらいたい」という
運用のために、Streamlit Community Cloud（無料）にデプロイして、
ブラウザの「データ登録」欄からExcelをアップロードできる仕組みを
用意しています。詳しい手順は別紙の設定ガイドを参照してください。
ここでは仕組みの概要だけまとめます。

- サイドバー下部の「📤 データ登録（Excelアップロード）」から、
  `data/incoming/` にファイルを置くのと同じ内容をブラウザ経由で登録できる
  （ローカルでフォルダに直接置く方法と併用可能）
- Streamlit Cloudの「Secrets」に `admin_password` を設定すると、この欄が
  パスワードで保護される（設定しなければローカル実行時と同様、誰でも
  すぐ使える状態のまま）
- Secretsに `github_token` / `github_repo` / `github_branch` も設定すると、
  アップロードのたびにファイルがGitHubリポジトリ側にも保存され、
  アプリが再起動してもデータが消えない（`.streamlit/secrets.toml.example`
  に設定項目の見本があります）
- Secretsに `viewer_password` を設定すると、**ダッシュボード全体の閲覧にも
  パスワードが必要になる**（正しいパスワードを入力するまでは、ロゴと
  パスワード入力欄だけが表示され、中身は一切見えない）。設定しなければ
  これまで通り、URLを知っている人は誰でもパスワード無しで閲覧できる
  状態のまま。店長さんたちには、このパスワードとURLをあわせて共有する
- パスワード入力画面には `assets/bigboss_logo.png` のロゴを中央に大きく表示し、
  鮮やかな青のグラデーション背景・ゴールドの縁取りカードでブランドに合わせた
  見た目にしている（ロゴ画像を差し替えたい場合は、同じファイル名で
  上書きすればよい）
- パスワード入力画面には、カーナビの雑学表示のように「本日は○○の日です」を
  日付・曜日と合わせて表示している（`lib/day_facts.py`）。ハッピーマンデーの
  祝日（成人の日・海の日・敬老の日・スポーツの日）や春分の日・秋分の日は
  年ごとに計算で求め、それ以外は広く知られている記念日を中心に一部の日付
  だけ登録している（全ての日を網羅しているわけではなく、該当が無い日は
  日付・曜日のみ表示される）。掲載したい記念日を追加・修正したい場合は、
  `FIXED_DAY_FACTS` の辞書に月日と名称を追記すればよい
- パスワード入力欄の下に、取り扱い注意事項（毎月月初にパスワードが変わり
  メールで案内すること、日々の確認が成長につながること、閲覧対象は
  役職者・店長に限られ責任を持って扱ってほしいこと、12時間で自動的に
  ログアウトされること）を明記している
- ログインは「ログイン」ボタン（Enterキーでも可）で行い、ログインから
  **12時間が経過すると自動的にログアウトされ**、再度パスワード入力が必要になる
  （実際にログアウトが反映されるのは、ブラウザ側で次に画面の操作や再読み込みが
  行われたタイミング）
- 毎月のパスワード変更・メールでの案内自体は、店長さんたちに手動でお願いする
  運用です（Secretsの `viewer_password` を月初に書き換えてください）。
  自動でパスワードを生成してメール送信する仕組みは今回は用意していません

## スマホのホーム画面に追加した時のアイコンについて

iPhoneのSafariなどで「ホーム画面に追加」をすると、通常はページの内容から
自動生成された簡易的なアイコン（文字だけのものなど）になってしまいますが、
`assets/bigboss_logo.png` のロゴがアイコンとして使われ、アプリ名も
「売上ダッシュボード」になるようにしています。ブラウザのタブに出るアイコン
（favicon）も同じロゴです。

Streamlitはページの`<head>`を直接編集する手段が無いため、
`render_home_screen_icon_tags()` が高さ1pxの見えないiframe経由で
`window.parent.document.head`に`apple-touch-icon`等のタグを追加しています
（`render_scroll_top_button()`と同じ「iframeから親ページを操作する」手法）。

iOSの「ホーム画面に追加」機能は、アイコンが`data:`形式（画像データを直接
埋め込む方式）だと認識してくれないことがあるため、`apple-touch-icon`だけは
実際にダウンロードできる画像URLを指定する必要があります。そのため
`.streamlit/config.toml`で`server.enableStaticServing = true`を有効にし、
`dashboard/static/bigboss_logo.png`を`/app/static/bigboss_logo.png`という
実URLとして公開し、それを`apple-touch-icon`のURLとして使っています
（ロゴ画像を差し替える場合は`assets/`と`static/`の両方を更新してください）。

## 今後の拡張候補

これはローカルで動く第一プロトタイプから始まっています。運用に合わせて
さらに以下を検討できます。

- フォルダを社内サーバーの共有フォルダに向け、定期実行（cron等）やファイル監視で
  自動更新する
- 店舗ごとの目標値（予算）を別シートで持たせ、予算比も表示する
- カテゴリ別・時間帯別など、Excelの列を増やした際の集計軸の追加
- 不正な値や未提出店舗をアラート表示する仕組み
